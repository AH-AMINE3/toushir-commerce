# Browser verification

Install with `npm ci` and `npx playwright install chromium`, then set `WEB_URL` to the explicitly enabled demo environment. Use `npm run smoke`, `npm run identity`, `npm run business`, `npm run warehouse` and `npm run map` individually. Reports/screenshots default to `reports/`; set `REPORT_DIR` to change it. Optional `CHROME_EXECUTABLE` selects an installed Chrome binary. Otherwise Playwright uses its managed Chromium.

Suites create isolated test records. Credentials stay in memory except when an explicit private fixture path is provided for the expanded journey. They must not target an unapproved commercial workspace. Initial unauthenticated requests and logout checks intentionally receive 401 responses. The identity report distinguishes browser console HTTP diagnostics from JavaScript exceptions; evaluate the named assertions as well.

Public demo creation is deliberately rate limited. Run suites with appropriate spacing or against a fresh local API process; do not weaken the public limit for tests.

The expanded journey suite (`npm run expanded`) checks a priced merchant checkout in the same actual authenticated workspace as the wholesaler, merchant activity periods and bar drilldown, categories/brands/barcode, all campaign mechanisms and gifts, region filters and CSV, analytics custom ranges, light/dark, loaded 3D assets, narrow layouts and the two-frame live hub. It creates two test sessions once and reuses their per-tab bearer identities. Optional `PRIVATE_FIXTURE` points to a private temporary JSON file so reruns and `npm run amendment` reuse those sessions; keep it outside source and report/artifact directories. The amendment suite requires that fixture and verifies the actual admin proposal form, exact merchant comparison, disabled acceptance before acknowledgement, consent and persisted updated quantity. `TEST_GROUPS` optionally selects named journey groups for targeted reruns; `REPORT_NAME` keeps their separate evidence. A full expanded run remains required for release.

`npm run expanded:review` reuses `PRIVATE_FIXTURE` to check the closed design-review fixes: a visible first product price and44px add target above fixed navigation at402x874, a received order awaiting confirmation, and a48px brand input without rail overlap. Its separate chart capture uses the actual payment ledger; absent negative values are not invented.
