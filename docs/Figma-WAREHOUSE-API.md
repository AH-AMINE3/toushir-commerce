# Counted lots, FEFO and barcode preparation

This module implements opt-in lot control and persistent pick waves. It does not invent batches for existing stock. Existing untracked products retain their previous behavior until a warehouse user records a physical count. Any order enrolled in a pick wave requires real scans even when its stock remains untracked.

All routes below start with `/api/admin/warehouse`. Reads and writes require the authenticated workspace. ADMIN/WAREHOUSE can mutate; DISPATCHER can read waves and lots; FINANCE can read lots. MERCHANT and DRIVER cannot read warehouse lots or tasks. Every mutation uses the shared transaction/filter; idempotency keys are scoped to workspace and actor, and a reused key with different contents fails with 409.

## API

- `GET /lots?productId=...`: `{product,stock,controls,items,policy}`. Selected `product` is `{id,name,barcode}` or null; `stock` is `{onHand:int|null,reserved,quarantined}` or null for an unknown product. An existing product with no offer has `onHand:null,reserved:0,quarantined:0`. `items` contain `{id,productId,productName,barcode,lotNumber,expiresAt,onHand,reserved,quarantined,initialQuantity,sourceKey,sourceRef,version,expired,eligibleAvailable}`. The selected stock projection lets WAREHOUSE bind an activation to the physical quantity they actually saw.
- `POST /activate`: `{productId,expectedPhysicalStock,reason,proofReference,idempotencyKey,lots:[{lotNumber,expiresAt?,quantity,quarantined:0}]}`. Maximum 200 distinct batches. `expectedPhysicalStock` must match the current physical value exactly, including null. No existing reservation or legacy quarantine may remain. This explicit count replaces physical stock, records its adjustment, creates counted batches, and enables FEFO. Expired batches may have quarantine but no sellable quantity. Replays return the current lots projection.
- `POST /lots/{id}/count`: `{version,quantity,reason,proofReference,idempotencyKey}`. Sets that batch's sellable physical count and adjusts the aggregate by the same delta. Cannot consume reserved stock, exceed the bounds, or declare expired stock sellable. Returns the lots projection.
- `POST /lots/{id}/quality`: `{version,quantity,disposition:"QUARANTINE"|"RELEASE"|"DESTROY",reason,idempotencyKey}`. Quarantine can only consume unreserved sellable units and creates a separate quality-hold source. Release/destruction of supplier or return holds must use their original inspection endpoint; this avoids leaving the origin's custody counters open. Expired holds cannot be released. Returns lots.
- `GET /waves`: `{items:[{id,workspaceId,name,status,createdBy,at}]}`.
- `POST /waves`: `{name,orderIds:[...],idempotencyKey}`. At most 100 distinct confirmed/preparing/ready orders before departure; a task can belong to one wave. Opening a wave resets manual preparation counts and sets PREPARING. Normal lines and current promotion gifts are separate tasks. Returns the wave detail below.
- `GET /waves/{id}`: `{wave:{id,workspaceId,name,status,createdBy,at},items:[{id,orderId,orderLineId,promotionSnapshotId,productId,productName,barcode,lotId,lotNumber,expiresAt,quantity,pickedQuantity,status,version,fefoManaged,isGift}],total,picked}`. Untracked tasks have empty `lotId`, null lot metadata, and `fefoManaged:false`; they are never represented as known batches.
- `POST /tasks/{id}/scan`: `{version,barcode,lotNumber?,quantity,idempotencyKey}`. Product barcode must match exactly; tracked tasks also require their exact reserved batch and a current non-expired date. Quantity is a positive increment bounded by the remaining task quantity. Replaying a scan cannot add units twice. All normal and gift tasks must complete before READY and departure; completion updates the persistent wave, order preparation, timeline, and the existing live invalidation channel. Returns wave detail.
- `POST /returns/identify`: `{sourceType:"CLAIM"|"REFUSAL"|"PROMOTION",sourceId,quantity,lotNumber,expiresAt?,proofReference,idempotencyKey}`. Identifies physically received quarantine without increasing aggregate stock again. CLAIM uses claim ID, REFUSAL uses order line ID, PROMOTION uses promotion snapshot ID. Routed refusals require the existing physical depot-return receipt before identification or inspection. Where original shipped batches exist, the number/date must match one of them and total identified returns for a batch cannot exceed its shipped quantity. Returns lots.

## Integrated stock rules

FEFO reserves the earliest valid expiration first, followed by oldest receiving time; undated batches are last. Reservations, release and departure change both aggregate and batch counters in the same transaction. Failed partial allocation rolls back. Availability for managed products excludes expired batches. Manual aggregate stock edits and quote stock changes cannot alter managed physical stock; use the count/quality/receipt workflow.

Supplier receiving creates an exact batch row for each receipt of a managed product. The existing supplier inspection updates its batch and source quantities together. Returns cannot re-enter sellable stock until their batch is identified and non-expired. A justified write-off may dispose of unidentified quarantine, but cannot make it sellable. Promotion gifts remain separate from paid lines throughout reservation, scans, custody, return and inspection.
